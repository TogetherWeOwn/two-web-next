# 2026-10-27 decision: server JS gzip ceiling 335360 -> 336384

`server.js.maxGzipBytes` rises 335360 -> 336384 in
`ci/budgets/kit/server-js.json`; no other ceiling changes. This admits the
event-capacity snapshot on the Kit admin event edit page: the Going-only
seat read, the shared capacity guidance copy and its pre-rendered panel
markup ship into the Kit server bundle through
`web/src/routes/admin/events/[key]/+page.server.ts`. Four 256B steps, the
smallest aligned cover for the measured worst case.

## Measurements

Locked Node 24.22.1 production builds (`npm run build --prefix web`),
measured through `node ci/check-kit-perf.mjs`, two builds of the feature
tree on pristine main `175da89db` (main's later commits touch no build
input).

| Tree | Server files | Raw bytes | Gzip bytes | Gate |
|---|---:|---:|---:|---|
| Pristine main | 116 | 1185177 | 335335 | exit 0, margin 25 |
| Feature build 1 | 116 | 1189013 | 336366 | exit 1 (earlier markup form) |
| Feature build 2 (final markup) | 116 | 1189016 | 336340 | exit 1, 980 over |

Worst case for the final tree is 336340: the current 335360 ceiling
rejects it by 980B, and 336384 (256 x 1314) admits it with 44B of margin.

(2551/1219B) and client CSS (2861/1019B) are unchanged; client JS grows to
54 files, 255285/102751B and fits its unchanged ceilings.

All growth is the feature: unique copy (snapshot, advice, seat rules,
range hint) and the panel markup renderer in `src/admin/event-capacity.ts`,
its call in `src/admin/kit-event-edit.ts`, and the one extra classified

`src/admin/rsvp-review.ts` precedent) so the Kit client bundle carries no
