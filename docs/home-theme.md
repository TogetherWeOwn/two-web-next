# Homepage theme

The purchased HTML landing page is the visual foundation for the homepage. Its centered landing composition, condensed uppercase typography, dark surfaces, ember-orange accent (#ff9c36, dark `#1d0b00` ink on it), square buttons, mirrored angular side details and compact account treatment are adapted to Hono SSR in `src/pages.tsx` and `public/theme.css`. The Lobby Ember brand applies the Logo 1 theme (violet-tinted night neutrals, Chakra Petch display over the Rajdhani fallback, Inter body) to that layout with no layout changes; `public/theme-tokens.css` plus the Kit mirror in `web/src/app.css` are the single-file swap point. The account reference contributes styling only: Discord OAuth, sessions, guild joins and logout remain the existing flows. There is no password/registration form.

The homepage, `/about`, `/faq`, `/rules`, `/privacy`, the `/join` landing, the community schedule (`/events`, `/events/past`), event detail/cancelled pages and branded error/OAuth recovery shells opt into the stylesheet through `Layout.theme`. The homepage and four content leaves (`/about`, `/faq`, `/rules`, `/privacy`) render it as a single generated inline `<style>` block (`src/leaf-critical-css.ts`, regenerated with `node ci/build-leaf-css.mjs`) allowlisted in `style-src` by its sha256 hash instead of a render-blocking stylesheet request; other themed routes keep the external stylesheet. They share the presentational `SiteHeader` and `SiteFooter`; error/recovery composition uses `RecoveryShell` without reading sessions or requiring a database. The content leaves use compact information navigation with a current-page indicator and readable policy text; Join uses a split content/preview layout that stacks on mobile. The 404 keeps optional event suggestions and labelled GET search below the centered status hero. The maintenance header and primary action link directly to the configured Discord invite, not OAuth. Member profiles opt into the base tokens through `theme="profile"` with layout details in the separate `profile-theme.css` sheet; the schedule does the same through `theme="schedule"` and `schedule-theme.css`, and event pages through `theme="event"` and `event-theme.css`. Other routes, including admin, retain their current layouts. Wrangler serves the external stylesheet, fonts and logos through the existing `public/` asset binding. No Bootstrap, jQuery, preloader, custom cursor, animation bundle, sample photos, original brand marks or third-party template folders ship. The decorative hero uses neutral CSS shapes instead of stock imagery. Feature images continue through the shared same-origin/approved public host policy, including validated configured hosts.

## Assets

- `public/fonts/display-latin-{500,700}.woff2`: Latin Rajdhani from `@fontsource/rajdhani` 5.3.0 (OFL-1.1), retained as the display fallback. Its unmodified font license is retained in `public/fonts/LICENSE.txt`. Two weights total roughly 31 KB. No remote font origin.
- `public/fonts/chakra-petch-latin-{600,700}-normal.woff2` + `public/fonts/inter-latin-{400,700}-normal.woff2`: Latin Chakra Petch (display, 600/700) from `@fontsource/chakra-petch` 5.3.0 and Latin Inter (body, 400/700) from `@fontsource/inter` 5.3.0 (both OFL-1.1, attribution in `public/fonts/OFL-ATTRIBUTION.txt`). Only the Chakra Petch 700 weight is preloaded; everything else fetches on use with `font-display: swap`. Content leaves (`/about`, `/faq`, `/rules`, `/privacy`) fetch no webfont at all and keep the system stack.
- `public/logo.svg`, `public/favicon.svg` and `public/icons/*.png`: the official Logo 1 vectors (gradient T in the broken octagon, `#ff9c36` → `#ff0e52` → `#5701ae`) and their renders, not template art. The header inlines the horizontal lockup SVG (180×50 desktop, 40px icon-only at ≤48rem); `/logo.svg` stays served for the JSON-LD organization logo. Verify the set with `python3 ci/generate-icons.py` (the old polygon generator is retired; the script only verifies now). The mark stays inside the maskable safe area. Existing install icon URLs, sizes and manifest identity are unchanged; `public/og-1200x630.png` is the 1200×630 share render wired as `og:image`/`twitter:image` on canonical pages.
- `public/theme.css`: adapted, explicitly opted-in base-theme rules (home, content/join, recovery), roughly 14 KB uncompressed against the 15360 B budget in `ci/bundle-budget.json`. Only hover/active feedback, with transitions gated by reduced-motion preference. No client script.
- `public/profile-theme.css`: profile-only layout under 8 KB, loaded only when `theme="profile"`.
- `public/schedule-theme.css`: schedule-only layout under 6 KB, loaded only when `theme="schedule"`. Every rule is scoped to `.events-page`, so the shared chrome stays in `theme.css`.

## Discord preview policy

The homepage Discord card links to `/join#join-heading`, where the preview and invalid/missing-guild fallback remain available as a click-to-load facade: a no-referrer link the visitor opens on request, never an embed on load. It does not embed Discord or initiate third-party widget requests on the homepage; the preview stays join-only. The versioned privacy disclosure (v2) still says the widget loads "when you scroll to it"; the facade is stricter (it loads only on click), so the v2 text is retained as a conservative description — the decision is recorded in the pull request. The new Open Discord link uses `/discord`, retaining its validated invite and hardcoded fallback for blank/rejected configuration. No policy history is rewritten or announcement claimed.

`discordWidgetUrl` accepts only a 10-25 digit configured guild ID for the join preview. The island builds the iframe only on click, keeping its title, fixed dimensions, no-referrer policy and `allow-scripts allow-same-origin` sandbox. The server CSP allows self-hosted fonts and permits frames only from `https://discord.com/widget` on `/join` GET and HEAD requests. Homepage and other routes/methods retain `frame-src 'none'`; script directives remain self-only, while `/` and the content leaves allow only their generated inline-style hashes in `style-src` (no `unsafe-inline`). Other routes retain the self-only style policy. Exact-head independent security review still applies.

Run only the relevant fixture suites locally; integration suites use the designated test database or CI containers, never staging/production databases.

The merged live counts/ranks reader and rank-stack rendering are retained, including zero/unclaimed and unavailable fallback semantics.
