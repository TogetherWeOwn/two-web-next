# Event page content readiness

Use this checklist before publishing a TWO Next event. Write for a member deciding whether and how to attend. The event form's event-specific fields are title, game, description, optional accessibility notes, start and end times, timezone, location, and capacity; the detail page also shows RSVP and attendance information. There are no dedicated purpose, host, or contact fields; put purpose and verified host details in Description where appropriate, and do not imply that a contact field exists.

## Before publishing

| Check | Authoring criterion | Current page/form contract |
|---|---|---|
| Title | Use a clear, specific event name that tells members what the event is. | Required; max 100 characters. Rendered as the page heading. Description is optional and appears under “About this event” only when non-empty. Add purpose to Description. ### Unknown or incomplete details

Label information that is unknown, tentative or still being arranged (for example, “joining link to follow” or “access details not confirmed”). Do not infer a location, timezone, host, accessibility arrangement, contact, schedule, capacity or RSVP availability from context. If a required publishing detail is missing, complete it before publishing rather than filling it with a guess. Description, Location, and accessibility notes are plain text; the app does not verify their accuracy or generate accommodation claims. There is no contact field. [Event form](../src/admin/pages/event-form-fields.tsx) · [moderator event workflow](moderator-admin-guide.md#create-edit-and-publish-an-event)

## Match copy to the current event state

Use the app's state and visible notice as the source of truth. Do not describe a draft, paused RSVP, cancellation, or past event as an open invitation.

| State | What the page currently does | Copy guidance | Source contract |
|---|---|---|---|
| Published | The event detail page is available to guests. It shows the title and available event details; RSVP controls depend on whether the event has ended, its RSVP setting, and capacity. There is no “Published” badge on the detail page. Publishing also attempts asynchronous Discord synchronization; it does not prove an announcement was delivered. | Describe it as published only after using the Publish action and confirming the public event page. Do not promise that RSVPs are open or that Discord has announced it unless separately verified. | [Admin publish flow](moderator-admin-guide.md#create-edit-and-publish-an-event) · [event detail page](../src/events/pages-detail.tsx) · [RSVP control](../src/events/rsvp-button.tsx) · [published journey](critical-journeys.md#critical-browser-journeys) |
| Draft | The page shows “Draft” to moderators; a non-moderator is refused with 403. Drafts are not public event pages. | Treat as internal work in progress. Do not share it as a public event or say members can RSVP. | [Draft access route](../src/events/routes-detail.tsx) · [event detail page](../src/events/pages-detail.tsx) · [draft-to-publish journey](critical-journeys.md#critical-browser-journeys) |
