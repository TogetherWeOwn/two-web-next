# Pure-Hono recovery ZIP profile

Use `decodePureHonoRecoveryZip` as the [offline validator](../ci/pure-hono-recovery-evidence.mjs)'s `decode` adapter. It returns `{path, bytes, type: "file"}` in central-directory order without extracting or executing anything. The validator checks the manifest and payload inventory separately. Synthetic fixtures do not authenticate evidence or qualify recovery. The route-evidence reader keeps its flat-name profile.

- **Layout:** One disk and a classic, uncommented end record at EOF immediately after the counted central headers. Reference each local record once. Together they must cover byte zero to the central directory without gaps or overlaps, in any order.
- **Encoding:** STORE (0) or raw DEFLATE (8), flags `0` or `0x0800` (UTF-8), creator `0x0314` (Unix ZIP 2.0), version needed `20` (`10` also works for STORE).
  External attributes carry a Unix regular-file mode in the high word (e.g. octal `0100644`), with only `0777` permission bits and a zero low word. Internal attributes are zero.
- **Agreement:** Local and central headers match on name bytes, version needed, flags, method, DOS timestamp bytes, CRC-32 and both sizes. No extras, comments, descriptors, ZIP64, encryption, directory entries, links or special files. Compressed input consumption, decoded size and CRC-32 must match the headers.
- **Paths:** `manifest.json`, `worker.js`, `effective-config.json`, or a file under `assets/`. Maximum 512 bytes and 32 `/`-separated components. Use only ASCII letters, digits, `.`, `_` and `-` in nonempty components; never end a component with `.`.
  Exclude DOS device stems (`CON`, `PRN`, `AUX`, `NUL`, `COM0`–`COM9`, `LPT0`–`LPT9`), even before extensions. No duplicates, case-folded aliases (including implicit directories), or paths that are both files and implicit directories.
- **Limits:** 64 MiB archive, 4,097 members including the manifest, 128 MiB expanded per member and total, 1 MiB manifest, 100:1 expanded-to-compressed ratio per member.
  Zero compressed bytes require zero expanded bytes. Use STORE when DEFLATE exceeds the ratio cap. Fail the archive if a payload cannot fit; never omit, rename or truncate members.

## Offline producer

[`packPureHonoRecovery`](../ci/pure-hono-recovery-packager.mjs) accepts an object with `worker` and `effectiveConfig` Buffers, `assets` (an array of `{ path, bytes }` with full `assets/` paths and Buffer values), `sourceSha`, `originalVersionId`, and an explicit `run` in the [normalized run adapter shape](../ci/pure-hono-recovery-run.mjs). The run must declare a completed, successful attempt on this repository's `refs/heads/main`, with the same source SHA and canonical string run/attempt IDs. The Worker and config must be nonempty; the asset list must have at least one member and can include zero-byte files.

The packager returns `{ archive, archiveSha256 }`. It writes payloads in ASCII path order, then `manifest.json`. The manifest uses compact UTF-8 JSON, the fixed `two.pure-hono-recovery.v1` schema and `two-web-next-production` target, and ordered file rows with exact byte counts and SHA-256 digests. ZIP timestamps and permissions are fixed; entry ordering does not depend on input order. Pin the returned digest to these exact bytes rather than assuming recompression with a different zlib version yields the same digest.

The API does no file discovery or I/O. It does not prove the Worker is pure Hono, the config is sanitized, the asset list is complete, or the supplied producer and version identifiers are authentic. The rollback selftest exercises synthetic bytes only. Production source capture, complete config projection, authenticated build/upload pairing, custody, and qualification are separate.

### Exact-source static asset inputs

[`inventoryPureHonoSourceAssets({ repo, sourceSha })`](../ci/pure-hono-recovery-assets.mjs) reads raw Git objects in a trusted local repository at a full commit SHA. It returns sorted `assets` records of `{ path, bytes }` with Buffer values for `bytes`, separate raw `controls` buffers or nulls, a compact JSON `receipt` buffer, and its `receiptSha256`. The receipt binds the commit, config and lock SHA-256, asset count and byte total, and byte counts and SHA-256 per selected asset and control. Checkout edits, untracked files and Git replacement refs cannot change its result.

The supported upload profile uses the root `wrangler.jsonc`, `--env production`, inherited `./public`, `ASSETS` and worker-first dispatch with unset HTML, fallback and base-path fields. The reader refuses tracked `wrangler.json` and `.wrangler` members that could shadow or redirect the config. The utility recognizes the exact lockfile integrity pins for [Wrangler 4.156.1](https://registry.npmjs.org/wrangler/-/wrangler-4.156.1.tgz) and [4.161.0](https://registry.npmjs.org/wrangler/-/wrangler-4.161.0.tgz). Both releases inherit the asset field as a whole, apply case-insensitive root exclusions, and read lowercase root `_headers` and `_redirects` separately for upload metadata. The receipt preserves exact UTF-8 control bytes, including a present empty file, apart from selected asset members. Matching names in subdirectories are ordinary assets. The input profile refuses root `.assetsignore`, root case variants of all three metadata names, root `_worker.js`-prefixed assets, legacy Sites, custom builds and environment asset overrides. A leading UTF-8 BOM is accepted in the config and retained in its digest.

The reader applies the ZIP path profile, refuses aliases and non-regular entries, and caps selected files at 25 MiB each, 128 MiB combined and 4,094 members. Each control and the config can use up to 64 KiB, the lock up to 2 MiB and the receipt up to 1 MiB. Checkout transforms, generated assets and CLI overrides can change the inputs Wrangler actually sees.

## Partial offline versioned config projection

[`projectPureHonoVersionedConfig`](../ci/pure-hono-recovery-config.mjs) accepts one explicitly supplied, normalized `scope: "versioned"` observation. It returns `{ partialVersionedConfig: Buffer }` with deterministic UTF-8 JSON and a trailing newline. The output schema is `two.pure-hono-versioned-config.partial.v1`. **Do not unwrap the Buffer and use it as `effective-config.json`.** The packager treats byte inputs as opaque. There is no complete config member producer yet.

The reviewed shape retains the script name, version UUID, compatibility date, `nodejs_compat`, the reviewed Hyperdrive ID for each of `DB` and `BOT_DB` and the two production producer queue names, the `ASSETS` and `CF_VERSION_METADATA` binding names/kinds, and exact reviewed public variable values. For required `secret_text` bindings only, an entry records name and presence (its kind); supplying a value or other metadata refuses. Missing bindings, unknown fields or kinds, swapped or unknown Hyperdrive IDs, and unreviewed public values refuse without echoing input. Review resource rotations before accepting new IDs. A normalizer is not provided: a future caller must bound the source bytes and the number of keys at each level before projection, and reject duplicate or unsupported fields during normalization. Exact shape validation enumerates own keys.

| Checked-in declaration or deploy behavior | Projection boundary |
| --- | --- |
| `wrangler.jsonc` root selects `src/worker.ts`, compatibility, observability, `./public`, `ASSETS`, and worker-first dispatch. Root placement, routes and bindings are not a substitute for production settings. | Compatibility and the asset binding only. Effective asset dispatch/HTML/fallback settings and header/control-file semantics still need observation; `./public` is a build input, not an effective setting. |
| `env.production` selects the production script and re-declares Hyperdrive, queue producers, version metadata and public vars. It disables placement, `workers_dev` and previews, names the production tail service and declares the apex domain and no crons. Secrets are outside the declarations; root `keep_vars` means the declared public vars are not an inventory of all effective bindings. | Script identity and the reviewed binding inventory above only. Any extra binding or setting in the versioned input refuses; additional observed version settings, including any limits or asset options, need their own reviewed shapes. |
| The Hono deploy dry-runs `--env production`, then uploads the built Worker as a version. Upload does not apply routes, custom domains or cron triggers. The tail Worker is deployed separately. | Non-versioned observations are not accepted. A complete member needs separately sourced effective routes/domains, schedules and consumer ownership, script settings (including tail, placement, observability and public endpoints as applicable), and asset/header handling, with versioned versus independent settings identified rather than inferred from source. |

The declarations above explain the allowlist, not what is live. No source capture or provider read-back is part of this API; it proves neither remote byte equality nor environment compatibility and authorizes no recovery or production operation.
